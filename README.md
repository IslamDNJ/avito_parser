# Мини-парсер объявлений Avito

Парсер ищет на Avito объявления по списку артикулов, оставляет только
новые товары из Москвы и Московской области, сортирует по возрастанию
цены и сохраняет по 5 самых дешёвых объявлений на артикул (или все
найденные, если их меньше пяти).

## Установка

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Зависимости: `requests`, `beautifulsoup4`, `openpyxl` (см. `requirements.txt`).

## Запуск

Список артикулов (из задания) захардкожен в `main.py` в константе
`ARTICLES` — при необходимости можно заменить своим списком.

```bash
# «боевой» запуск — реальные запросы к avito.ru
python main.py --output result.csv
python main.py --output result.xlsx

# офлайн-режим — тот же код парсинга/фильтрации/сортировки,
# но на локальных HTML-файлах из fixtures/ вместо сети
python main.py --test-mode --output result.csv
```

## Как задаются регион, состояние и сортировка

- **Регион** — задаётся выбором раздела в самом URL поиска:
  `https://www.avito.ru/moskovskaya_oblast?...`. Этот раздел на Avito
  объединяет Москву и Московскую область, поэтому один запрос уже
  ограничен нужным регионом на стороне Avito. Дополнительно на стороне
  парсера (`avito_parser.filter_and_rank` → `_is_allowed_region`) есть
  проверка по тексту адреса карточки (город/район) — это защита «на
  всякий случай», если в выдачу попадёт что-то не из региона.
- **Состояние товара** — параметр `state=new` в поисковом запросе
  (см. `SEARCH_PARAMS` в `avito_parser.py`). Если на карточке всё же
  явно указано «Б/у», такая карточка дополнительно отсекается в
  `filter_and_rank`.
- **Сортировка по цене** — параметр `s=104` (сортировка по возрастанию
  цены) в URL запроса, плюс сортировка ещё раз выполняется в самом
  парсере (`kept.sort(key=lambda x: x.price)`) после фильтрации —
  чтобы порядок гарантированно был верным независимо от того, как
  Avito фактически отсортировал выдачу.

Все константы (`BASE_URL`, `SEARCH_PARAMS`, список городов МО для
проверки региона) вынесены в начало `avito_parser.py` и снабжены
комментариями — Avito время от времени меняет разметку/параметры, и
это первое место, куда стоит смотреть при поломке.

## Структура

```
avito_parser.py   — основная логика: URL, запрос, парсинг HTML, фильтрация, ранжирование
main.py           — CLI: список артикулов, запуск пайплайна, запись result.csv/xlsx
fixtures/         — тестовые HTML-страницы (свои, не от Avito) для --test-mode
result.csv        — результат прогона (пример, офлайн-режим)
result.xlsx       — тот же результат в Excel
```

## Обработка ошибок и блокировок

Прямые запросы к avito.ru с обычного HTTP-клиента (без браузера)
блокируются самим Avito (в моих прогонах — HTTP 403). Обходить это
защитой Avito по условиям задания не требовалось, поэтому:

- при недоступности страницы / сетевой ошибке / неожиданном статусе
  для артикула сохраняется одна строка со статусом `ошибка`;
- если запрос прошёл, но подходящих объявлений не нашлось — строка со
  статусом `не найдено`;
- чтобы можно было проверить сам пайплайн (парсинг → фильтры → топ-5)
  без сети, есть `--test-mode`, который подаёт на вход парсеру
  собственные тестовые HTML-файлы из `fixtures/` вместо живой
  страницы Avito. Это ровно тот сценарий, о котором сказано в задании
  на случай блокировки прямого запроса.
- цена приводится к `int` (или `None`, если её не удалось распознать);
  объявления без числовой цены не участвуют в отборе топ-5;
- повторяющиеся объявления (одинаковый URL) в рамках одного артикула
  схлопываются в одну строку.
